# 宿伴 Soulband Android 原生预览版

版本：v0.3.0 · 日期：2026-11-05。

本版采用 Kotlin 与 Android 原生 Activity/Service，提供配对、授权、手机状态采集、上报、提醒收件箱及系统通知。它不是手机网页封装；公约协商、值日和账单的完整原生页面尚未实现。

安装包位于项目根目录 `output/apk/Soulband-v0.3.0-debug.apk`，面向 Android 10（API 29）及以上，属于已签名的调试预览包，不是应用商店发布版。

目标试用手机为用户提到的 iQOO 12；具体 Android/OriginOS 版本尚未确认，当前无已连接手机，因此未宣称真机兼容性或后台稳定性已经验证。

## 安装与联调

1. 电脑双击 `soulband-demo/启动手机联调服务.cmd`，保持服务窗口开启。它将服务监听改为局域网可访问，并列出本机实际 IPv4 地址，不会自动修改防火墙。
2. 在电脑浏览器打开 `http://127.0.0.1:8765`，选择自己的演示身份，进入“演示与设置 → 原生 Android 配对与采集”。
3. 点击“为某某生成手机配对码”。配对码 5 分钟有效、只能使用一次；重新生成后同成员旧配对码失效。
4. 将 APK 传到手机安装。也可以在同一局域网用手机访问 `http://电脑实际局域网IP:8765/downloads/soulband.apk` 下载，地址以服务窗口实际输出为准。
5. 手机打开宿伴，填写 `http://电脑实际局域网IP:8765` 和配对码。HTTP 测试须明确勾选提示，仅允许局域网地址；使用可信 HTTPS 服务时保留正常证书校验，不接受忽略证书错误。
6. 配对后，手机显示绑定成员。在手机点击“打开使用情况访问权限”，按系统页面为宿伴授权；点击“允许提醒通知”完成系统通知授权。
7. 主动点击“开始采集并接收提醒”。常驻服务通知提供暂停入口，应用内显示最近上报、亮屏和锁屏等状态。
8. 电脑概览中该成员的手机变为原生 Android 来源，不能再用模拟下拉框覆盖。可暂停采集；需要切回模拟时先在电脑解除配对，再点击“当前身份手机切回模拟”。

仅启动桌面版时服务默认监听本机，手机无法连接。连接失败需检查实际地址、网络是否可互访和系统防火墙，不应通过关闭全部防火墙来处理。电脑与手机不在可互访的网络时，本版没有外网穿透功能。

正式账号与完整 Web 权限隔离仍未完成，联调服务仅在可信测试局域网使用样例数据。原生手机接口有单独的配对凭据校验，不代表现有全部演示接口已经完成正式鉴权。

## 体验一次手机提醒

1. 电脑端生成公约，让四个演示身份分别确认。
2. 为绑定成员将通知偏好设为“主要通知手机”或“两端均提示”。
3. 手机完成授权并开启服务；在手机应用中操作会产生本人交互依据。其他设备可暂时保持明确标记的模拟状态。
4. 确认当前处于公约静音时段。可在联调时选择模拟业务时钟，但设备采样有效期始终按实际时间计算。
5. 等待自动判断，或在电脑点击“体验主动提醒”。提醒目标包含该手机时，原生服务尝试拉取新消息并显示系统通知，也可在手机点击“刷新我的提醒”。
6. 点击“我已读到”同步服务端已读状态。服务下一次同步时会撤下已读消息的通知。

手机通知采用用户开启的前台服务定期轮询，不是远程推送平台。系统通知权限、系统省电、应用存活、网络和通知设置都会影响到达时间，不能保证锁屏/后台即时送达。

## 状态采集与隐私

- 使用 [UsageStatsManager](https://developer.android.com/reference/android/app/usage/UsageStatsManager) 查询必要交互事件，并在本地归纳时间摘要。使用情况访问需用户授权，权限或数据不可用时上传未知依据。
- 只读取事件类型及时间，不读取或上传应用名称、类名、使用明细、事件 extras、屏幕或按键内容。[USER_INTERACTION](https://developer.android.com/reference/android/app/usage/UsageEvents.Event#USER_INTERACTION) 表示用户交互事件；屏幕亮起本身不算明确操作。
- PowerManager/KeyguardManager 提供当前屏幕交互态和锁屏状态。近期明确交互且未锁屏可作为有活动证据；只有亮屏、没有明确交互时保留不确定。
- 熄屏或锁屏的持续观察达到初始 1200 秒才上传持续无活动证据，不认定已经睡着。亮屏、明确解锁或新的交互会重置观察，避免漏掉中间短暂操作。服务刚启动时不会凭历史锁屏状态补出已经观察 20 分钟。
- 手机每次任务结束后约 15 秒尝试新采样和上报；宿主以采样时间设置最长 90 秒有效期。Doze 或厂商省电可能延迟任务，过期即未知，不把断线当作休息。
- 不保存离线使用明细。断线恢复时生成新采样，旧时间戳和重复序号不能刷新有效期。
- 暂停请求与采样使用递增序号，较旧的在途上报不能把已暂停状态覆盖为活动；重新开始可以发送更新序号。
- 手机凭据保存在应用私有数据内，不写界面、URL 或日志；禁用备份并排除数据迁移。服务端仅保存凭据哈希，不在公共状态接口返回配对码或凭据。
- Android 14+ 的采集服务声明了 [specialUse 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)，由用户在界面主动启动并提供常驻通知；这不代表已通过任何应用商店审核。

阈值为预览实现配置，不是经过 iQOO 真机验证的最佳参数。屏幕/锁屏信号不等于噪声或违规，成员综合判断仍走现有公约和模型流程；真实采集与 Ollama 模式独立。

## 构建

本次使用 JDK 17、Gradle 8.13、Android Gradle Plugin 8.13.1、Kotlin 2.0.21、SDK Platform 35 和 Build Tools 35.0.0。依据 [AGP 8.13 兼容表](https://developer.android.com/build/releases/agp-8-13-0-release-notes) 选择构建工具，未为追求最新版本更换已有环境。

在本目录运行：

```powershell
.\Build-APK.ps1 -JdkHome 'D:\JDK17' -SdkRoot 'D:\SoulbandBuild\android-sdk'
```

其他电脑使用自己实际安装的路径，或设置 `JAVA_HOME` 和 `ANDROID_HOME`。脚本生成本地 SDK 配置，运行 `assembleDebug lintDebug`，成功后复制 APK 到 `output/apk/` 并计算 SHA256；不运行批量删除。

已附 Gradle Wrapper。首次构建可能需联网解析依赖。项目路径含中文，当前构建开启 Android 路径检查覆盖选项；仍需注意不同机器的路径兼容性。

Android SDK 工具位于 `D:\SoulbandBuild\android-sdk`，本次复用了 `D:\JDK17` 与已有 `D:\Gradle` 缓存，没有修改全局 Java 环境变量。

- 原生系统通知、通知栏暂停、手机已读和电脑已读同步。

若使用 USB，需在手机上自行启用适用的调试设置并确认授权。确认只有目标手机后可执行：

```powershell
D:\SoulbandBuild\android-sdk\platform-tools\adb.exe devices
D:\SoulbandBuild\android-sdk\platform-tools\adb.exe install -r ..\output\apk\Soulband-v0.3.0-debug.apk
```

出现多台设备时应先确认目标序列号，再用 `adb -s 实际序列号 install -r ...`，本次未自动安装到任何手机。
