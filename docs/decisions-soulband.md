### D021｜v0.5 修复到期死锁与改为定时调度
- 背景：复核实测发现公约到期后只在读取副本上标记过期，数据库仍保留生效指针，于是加成员被 409 挡住、撤销又提示「没有生效公约」；提醒靠每 3 秒比对含业务时钟的输入签名，真实模式下每个静音时段会重跑多次两阶段推理。
- 结论：到期改为存储层统一投影（读取即清理生效指针并标记 expired）；新增 `scheduling.py`，持久化下次触发时间，定时器只在静音时段起点触发一次，迟到不超过 15 分钟补发，超过记为「已错过」并用上次时段防止每 tick 重复上报。
- 边界：错过不补发过期提醒；触发后仍走原有模型或模拟判断分支，程序不替代判断。
- 验证：新增 8 项测试覆盖到期、加成员、触发、错过、时钟跳动不触发与合并提醒。
- 日期：2026-11-08。

### D022｜公约生效不再依赖模型记录
- 背景：最后一位成员确认时会调用模型记录公约；Ollama 不可用时返回 502，公约永远无法生效，演示现场会卡死。
- 结论：模型记录失败时由程序写入受控回执并显式标注「降级」，同时在追踪里记录「模型记录降级」；回执只含工具名、公约编号和条款数，不含模型叙述。模拟模式失败仍然报错，保持「无静默回退」。
- 日期：2026-11-08。

### D023｜同机四座位演示
- 背景：四人协同无法在评审现场靠四台设备演示，但也不能为了演示绕开鉴权。
- 结论：宿主本机可签发 7 天座席会话（`POST /api/demo/seat`），四个浏览器窗口各自持有 token，身份由服务端会话决定，`X-Member-Id` 无法冒充他人；座席不能加成员、改设置或操作设备授权；校验与会话表同一套，不是后门。
- 限制：座席仅限宿主机本机申请；关闭窗口后会话保留 7 天，`GET /api/demo/seats` 可看在线状态。入口 `启动四座位演示.cmd`，使用独立库 `data/seats-v0.5.sqlite3`。
- 日期：2026-11-08。

### D024｜私密诉求卡独立存储
- 背景：v0.4 的私密诉求卡随整库 JSON 落盘，只在展示层按人过滤，与「私密不落共享状态」的说法有落差。
- 结论：私密卡片改存 `private_needs` 表，不进入共享状态、导出和页面快照，仅本人可读；旧库里已存在的私密卡片在读取时迁移进表。
- 日期：2026-11-08。

### D025｜增量同步与本地持久化
- 结论：`/api/state` 支持 `since` 游标，页面 3 秒轮询在无变化时只回填运行时信息；SQLite 开启 WAL 与 `busy_timeout=5000`；启动与手动备份使用 VACUUM INTO + JSON 导出，保留最近 7 份。
- 未做：仍是无推送的轮询，没有引入 WebSocket；备份不自动恢复到新版本，恢复需手动替换数据库。
- 日期：2026-11-08。
