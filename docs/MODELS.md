# 大模型连接

双击 `一键启动宿伴.cmd` 后，首次在界面选择模型来源；打开软件不会默认下载模型。

- **本地大模型**：默认模型名 `qwen2.5:7b`。点击“保存并准备本地模型”才检查、下载和启动 Ollama 与模型，进度在设置页显示。已保存的本地选择在以后启动时会继续准备。
- **外部大模型**：填写 API Base URL、服务商模型名和 API Key，可先“测试连接”再保存。使用 OpenAI Chat Completions 兼容接口及 JSON 输出；不安装或启动 Ollama。原生 Claude/Gemini 等不同协议需要兼容网关。

Base URL 例如 `https://api.openai.com/v1`，也支持完整 `/chat/completions` 地址。除本机调试外必须使用 HTTPS。API Key 留空只保留该地址已保存的密钥；更换地址需要为新地址填写密钥。

外部调用会将该次任务所需的诉求、公约、设备摘要或私密表达发送给服务商，可能产生费用。界面显示数据发送提示；不会把外部服务描述为本机推断。

密钥放在当前业务数据库旁的 `*.model-credentials.sqlite3` 独立本机凭据库，不进入共享状态、活动日志或业务数据库备份。凭据库为本机明文存储，不要外发该文件或整个 `data` 文件夹。成员端不能修改连接、测试连接或发起模型下载。

“演示模式”保留在设置页和四座位入口，结果始终标记为模拟。真实模型调用失败时不会自动切换模拟。

开发接口：`PUT /api/settings` 保存配置，`POST /api/settings/test` 测试未保存的配置，`POST /api/settings/local-setup` 显式准备本地模型，`GET /api/settings/local-setup` 查看进度。状态 `mode` 为 `unconfigured`、`ollama`、`external` 或 `demo`。新增外部模式不要求成员设备安装模型。

验证使用本机模拟的 OpenAI 兼容服务，不代表已验证任意第三方平台或实际模型质量。

模型选择功能验证：92 项后端测试、21 项浏览器检查通过。随后加入桌面故障恢复时，完整后端套件为 103 项通过。早期关闭沙箱的离屏测试不能作为正常桌面渲染通过的证据。本次已定位退出码 17/渲染器退出码 18 的原因：虚拟环境 Python 与 Qt 可执行文件、DLL 被错误标记为 Windows Low 完整性。恢复正常 Medium 标记后，沙箱保持开启的完整 Windows 原生窗口检查已通过，模型选择页和 JavaScript 均正常加载。桌面启动脚本已增加对应检查和修复。

Qt 失败时仍保留默认浏览器备用入口；也可用 `启动宿伴_浏览器.cmd` 跳过 Qt。控制台提供地址、重试默认浏览器和尝试 Edge 的选项；自动打开失败也保留服务供手动访问。浏览器方式没有 Qt 托盘通知，应用内提醒仍可使用。浏览器故障恢复检查使用注入的工作进程失败和测试浏览器，与真实原生窗口检查分开记录。未下载新模型、未调用真实外部 API；Android 仅同步模式与外发提示源码，未重建 APK。
